# HeliLog V2.3 — Login-first Cloud Sync Test

**Testing release only.** The stable V1 site and pre-cloud V2.2 test data remain untouched.

## What's new

- HeliLog now displays a full-screen sign-in before any private logbook page. Uses the existing invite-only Supabase project (email/password); existing authenticated sessions can resume online.
- Each Supabase pilot account gets a separate browser-local cache under its verified user UUID. Old V2.2 demo flights/sandbox data stay under their existing keys and are **never automatically imported**.
- **Aircraft and flight records only** synchronize to the owner's PostgreSQL records with row-level security.
- New records upload and appear on the other authenticated device when the app refreshes (manually, on window focus, after reconnecting, and periodically while visible).
- Edits and deletions use revision checks. A conflicting change is not overwritten; an unresolved conflict stays pending and needs later manual-resolution tools.
- Pending operations are saved on this device. Flights recorded after an authenticated session while offline remain queued. **Signing in from a fresh or signed-out device still requires internet.**
- Sign out ends the Supabase session and hides the logbook; account-specific device cache is retained so pending edits are not destroyed.

## Important limitations

**Not yet synced in V2.3:** endorsement text and signatures, instructor/pilot profiles, medical and licence details, simulator-specific metadata outside flight entries, brought-forward totals, archive page histories, and signed correction addenda. These remain *local to the current device*, and aren't safe to rely on for cross-device recovery.

Paper print archives and signed corrections are intentionally paused in the new cloud workspace until cloud snapshots and corrections can be stored atomically and immutably. Old archived V2.2 data remains separate and unchanged.

**No cloud migration** of the old V2.2 local logbook is performed automatically. The full JSON backup restore into a cloud workspace is blocked to avoid replacing synchronized flight records. Original backup/export files can still be saved for safety.

This release does **not** deliver offline login, conflict resolution, regulatory certification, verified electronic signatories, encryption of local browser storage, or production-safe cloud backups. Continue with **fictional test data only**.

## Suggested manual acceptance test

1. On the web browser, open the staging V2 site and sign in using the existing private Supabase account. Confirm the Dashboard opens and the cloud workspace begins empty.
2. Add fictional aircraft **LY-TEST**, ICAO **G2CA**, then save one fictional flight referencing it.
3. Wait until the status reads **Cloud synced**.
4. Open the V2 PWA on an iPad, sign in using the same account, and verify both aircraft and flight appear. If not, tap **Cloud account → Check / sync now**.
5. Add another fictional flight on iPad, wait for sync, then open the desktop and trigger a refresh. Verify the flight appears without a duplicated aircraft.
6. Disconnect a previously signed-in iPad, add a fictional flight, and confirm **pending/offline** is shown; reconnect and verify the flight reaches the cloud.
7. Verify full-paper printing and archive controls are unavailable inside the cloud workspace, that a signed-out device cannot display the logbook, and the legacy V2.2 data has not been automatically imported.

Avoid concurrently editing the same flight on two devices until conflict resolution is implemented. A detected conflict is preserved but not automatically resolved.

## Development verification

Automated simulated checks cover local-scoped account data, new aircraft and flight uploads, another device retrieving records, cross-user isolation, revision conflicts and offline queues; a full-browser mock verifies first-login restoration and successful aircraft upload. **Real device and live Auth testing are required before considering V2.3 accepted.**
