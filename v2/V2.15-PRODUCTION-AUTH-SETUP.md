## Dashboard setup — required before inviting anyone

Open `https://supabase.com/dashboard/project/xvmzvoldlajvnfxonrvn` and verify:

1. **Authentication → General / Sign In / Providers**: Turn **Allow new users to sign up OFF**; turn **Allow anonymous sign-ins OFF**; keep the **Email** provider enabled and **Confirm Email ON**. Supabase menu labels may vary.
2. **Authentication → URL Configuration**: Set Site URL to `https://helilog-pwa.onrender.com/`; add the **exact** Redirect URL `https://helilog-pwa.onrender.com/?helilog_recovery=1` for HeliLog's Forgot password link. Do **not** add the TEST hostname to Production redirects, or broad `**` wildcards.
3. **Authentication → Emails → Templates**: Check **Invite user** and **Reset password** templates. Supabase's default `{{ .ConfirmationURL }}` link should reach the configured Site URL after verifying an invite. Reset links must honor the chosen `redirectTo` and land on the `?helilog_recovery=1` page. Supabase default email templates are sufficient until custom SMTP is available.
4. **Authentication → Emails → SMTP Settings**: Configure a reliable, verified custom SMTP sender and From address **before inviting friends**. Supabase's built-in sender is restricted to authorized team addresses and is rate limited. Set SPF/DKIM/DMARC and verify delivery. Do not share SMTP credentials in a chat or source code.
5. **Authentication → Rate Limits and Attack Protection**: Review sign-in, reset, and invitation throttling. Keep recommended protections enabled. **Leaked-password protection is a paid Supabase feature** per current pricing; do not upgrade the organization without explicit cost approval.
6. **Authentication → Users**: Once all settings are confirmed and an isolated production candidate website is live, choose **Add user → Send invitation** for a fictional test user. The user should receive an invite link with a Supabase `type=invite` callback, choose a password, sign in, and complete an empty pilot profile. If this flow differs for your configured Auth flow, stop for review instead of bypassing the session check.

## V2.15 tested application behavior

- Password-reset email flow remains separate and requires `?helilog_recovery=1` plus a verified `type=recovery` token/session match.
- New invitation acceptance detects a `type=invite` callback and verifies that both recovery/link tokens and the live Auth session match the returned identity.
- User chooses a password of 6–128 characters and confirms it. A longer unique password is recommended; a stricter Supabase Auth minimum takes precedence.
- After password setup, the temporary session signs out globally. User signs in normally, then completes their private pilot profile.
- Invalid/expired invitations do not unlock the logbook, and **Back to sign in** revokes the temporary session before returning to login.
- No new invitation flow has been tested end-to-end with real external email delivery; automated tests use fictional tokens and identities only.
