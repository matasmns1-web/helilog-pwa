# HeliLog V2.8.2 — App → Web Archived-Flight Correction Test

**Test only:** Use fictional flight records and the V2 test account. This is not certification of an electronic logbook.

## New workflow

1. Archive a fictional flight in **HeliLog Web**. This protects its original cloud record and paper archive snapshot.
2. Open the same archived flight in the installed **HeliLog app**. **Propose correction** now opens the normal flight or simulator edit form, with required correction reason, instead of showing the old desktop-only alert.
3. Change a fictional value (for example flight time or remarks), enter a reason and tap **Propose correction**. The app saves a **pending proposal**, not an edit of the archived flight.
4. If the app is online, wait for **Cloud synced**. If offline, the change remains in its account-scoped local queue and uploads on reconnect (or via **Cloud account → Check / sync now**).
5. Open HeliLog in a regular web browser, sign into the same account and **Check / sync now**. Go to **Print archive**; find the pending correction addendum.
6. **Print/review, sign, then confirm** the addendum on the web. Only web confirmation changes effective flight totals and signed correction history. It does not rewrite the original archived flight.
7. Return to the installed app and synchronize. The confirmed correction and effective flight details should appear; **no duplicate pending proposal** should remain.
8. Reopen the original archive batch to verify the signed original still reflects the original flight data.

## Expected protections

- Other devices need not be online during web confirmation; they can refresh afterward.
- Database uniqueness prevents two **active** cloud proposals for the same archived flight. Competing local proposals are not merged automatically; preserve both drafts and resolve their conflict manually.
- A signed addendum is saved by the existing owner-verified database RPC. A database trigger retires the matching draft **within that same transaction**, even if the originating app is offline.
- If you press **Propose correction** while another proposal is pending on the same device, you are directed to complete/review it rather than silently replace it.
- Apps can propose corrections but **cannot print, sign or confirm addenda**.
- Deleting a pending draft on the web uses account-scoped revision-checked synchronization; confirmed addenda cannot be edited or deleted.

## Known limits

- All records remain for **fictional testing**; the app is not verified for EASA acceptance.
- An offline device that has never signed into its cloud account cannot open the account offline.
- Unresolved cross-device conflicts are not automatically adjudicated. Do not clear browser/app storage as a workaround.
- Cloud backups and disaster recovery remain manual/limited as noted in the V2.8 guide.
