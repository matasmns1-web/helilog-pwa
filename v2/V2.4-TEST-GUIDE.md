# HeliLog V2.4 — Extended cloud sync testing

**Test website only:** https://helilog-v2-test.onrender.com. V1.43.2 stable remains unchanged.

## What V2.4 adds

After opt-in, the existing Supabase account can synchronize saved pilot/instructor profiles, qualifications, medical details, brought-forward totals, and signed endorsements in addition to V2.3 aircraft and flights. New prints/archives may be confirmed in a web browser once all queued edits have synchronized and cloud archives are verified.

**For your three devices, activation order matters:**

1. Sign in on the device containing the best/most complete endorsement and profile information. Go to **Cloud account → Upload this device's remaining records**. Confirm the upload once and wait for **Cloud synced**.
2. On the other two devices, go to **Cloud account → Use existing cloud records**. This backs up their existing local profiles and endorsements before replacing these *additional* fields with the cloud version.
3. Do not choose upload from a second device after the first has already uploaded. It will be blocked.
4. Add a FICTIONAL endorsement on the installed app, sign it, wait for **Cloud synced**, then open HeliLog in a web browser. The signed endorsement should appear.
5. On the web only, preview, print and confirm one fictitious endorsement archive batch. After refreshing the app, it should display the archived status. Verify exact page reprinting and no changes to signed originals.

Your existing V2.3 synced aircraft and flights are unchanged by opt-in. Unsynchronized additional records from another device are saved in that device's backup at **helilog_v24_pre_extension_<account UUID>** before the extra data is replaced; this is an internal device-local backup, not an independently verified remote restore.

## Pilot profile conflict recovery (web or installed app)

If **Cloud account** shows **Conflict: needs attention** for `settings:pilot`, do not reset the account or delete browser data. Open **Cloud account → Review pilot profile conflict**. HeliLog compares each different field in the web/device profile and the cloud profile, without overwriting either version.

- **Keep this web profile**: after you confirm, only the pilot settings record is queued for a revision-checked update to the cloud; other devices will receive it on their next sync.
- **Use cloud profile on this device**: adopts the current cloud pilot settings locally and does not upload a new pilot record.

Both options first save a device-local safety snapshot of the entire account workspace and both profile copies. The operation is stopped if the cloud revision changed since preview or if that safety snapshot cannot be written. If changes were made elsewhere meanwhile, review again. Confirm that **Cloud synced** appears afterward.

This is a targeted recovery for `settings:pilot` only. Do not use it to resolve other conflicts or signed archive issues.

## Critical limitations

- This is **test-only**, not an EASA-approved or production-certified record system.
- Signatures are still captured PNG images and **do not establish verified instructor/examiner identity**.
- Database row-level policies protect private ownership; signed endorsement rows become sealed when signed data is uploaded. Archived batches and corrections are written by owner-checked database functions and the originals remain immutable.
- Do not archive or print if the sync status is **Pending**, **Offline**, **Conflict** or **Error**.
- Signed endorsement corrections and print archives are available only on the web browser, not the installed PWA.
- Conflict resolution and full offline account unlocking are not implemented. If changes conflict, preserve both devices and ask for help rather than deleting data.
- The migrated database already contained V2.3 aircraft/flight test records; no existing flights were erased by migration.
- **Do not enter real flight histories or personal medical records until security, backup restoration and identity-signing validation are completed.**

## Validation

- V2.3 aircraft/flight sync remained opt-in-compatible in simulation.
- V2.4 extended sync test passed for primary upload, second-device retrieval, preserved local backup, and rejecting conflicting uploads.
- Archive adapter blocks confirmation while offline or not fully synced and refuses installed-app print confirmation.
- PostgreSQL migration adds permanent sealing of signed records and transactional print archive RPCs. Supabase security advisor may flag the intentional elevated archive functions as requiring further review. All functions must remain restricted to authenticated pilots and their own records.
