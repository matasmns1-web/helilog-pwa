# HeliLog V2.16 — Google sign-in setup (no HeliLog domain or SMTP required)

**Status:** Front-end Google OAuth flow is prepared on the **HeliLog Test** site, but Google sign-in will not complete until the OAuth provider is configured in Google Cloud **and** Supabase. Do not turn off existing email/password sign-in. No test records, signed archives, or production database records are migrated.

## Step 1 — Configure Google Auth Platform

Open [Google Cloud Console](https://console.cloud.google.com/auth/overview). Create/select a project for HeliLog beta. In Google Auth Platform, configure Branding, Audience, and Data Access. Choose **External** for personal Gmail users, then create a **Web application** OAuth 2.0 client.

For the **HeliLog Test** configuration:

- **Authorized JavaScript origin:** `https://helilog-v2-test.onrender.com`
- **Authorized redirect URI:** `https://cabfifnsxpaalgsyicbo.supabase.co/auth/v1/callback`

For later production rollout, use a **separate OAuth client** (preferably a separate Google Cloud project for proper test/production separation):

- **Authorized JavaScript origin:** `https://helilog-pwa.onrender.com`
- **Authorized redirect URI:** `https://xvmzvoldlajvnfxonrvn.supabase.co/auth/v1/callback`

Only request the basic identity scopes `openid`, `email`, and `profile`. No Google Drive, contacts, mailbox or calendar permissions are needed. **Keep the Google OAuth client secret private; never paste it into ChatGPT or commit it to GitHub.**

**Access-control warning:** Google's **Testing** audience and test-user list are useful for development but are **not sufficient access controls for the basic identity scopes**, which may be available outside Google's tester list. The login link is not an authorization boundary. If only specific friends should be allowed, implement and test a **server-side Supabase sign-up allowlist / Before User Created hook** before accepting new users. An app-side hidden signup button or client-side email list is not sufficient.

## Step 2 — Connect Google on Supabase TEST

Open [HeliLog Test → Auth Providers](https://supabase.com/dashboard/project/cabfifnsxpaalgsyicbo/auth/providers) and turn on **Google**, supplying the Google Cloud client ID and client secret. Confirm the callback URL displayed by Supabase matches the exact URI above.

Open [HeliLog Test → URL Configuration](https://supabase.com/dashboard/project/cabfifnsxpaalgsyicbo/auth/url-configuration):

- **Site URL:** `https://helilog-v2-test.onrender.com/`
- **Additional redirect URL:** `https://helilog-v2-test.onrender.com/?helilog_oauth=google`
- Keep password recovery redirect `https://helilog-v2-test.onrender.com/?helilog_recovery=1` where already configured.

**New Google users:** In Supabase Auth general settings, **Allow new users to sign up must be ON** for first-time Google users. With signup disabled, only existing users can sign in. Keep anonymous sign-ins OFF. Google sign-in with verified email does not require Supabase's SMTP invitation emails. Email/password login remains available to existing accounts, but emails to external recipients will remain restricted until SMTP is configured. Enabling signups without a server-side allowlist lets additional users create accounts.

## Step 3 — Test on staging

Once configuration is complete:

1. Open the [HeliLog V2 test website](https://helilog-v2-test.onrender.com/) in a private browser window, and select **Continue with Google**.
2. Choose a Google account that has not previously been registered in HeliLog Test. Google redirects through the **test Supabase** callback, then back to `?helilog_oauth=google`. The callback token/session must match and be verified before the app unlocks.
3. Complete the new pilot profile. Confirm an empty logbook and create an entirely fictional aircraft/flight.
4. Sign out and in again with Google. Confirm the same account and same private data return.
5. Sign in to an existing email/password account on another device. Confirm neither account can see the other's information.
6. Cancel the Google dialog and check the error is shown without opening a logbook.
7. Repeat installed PWA sign-in after first validating in the regular browser.

**Account linking:** A pre-existing email/password account may or may not be linked automatically to its Google identity depending on Supabase's identity-linking rules and verified email. Confirm the resulting user ID before expecting the two login methods to share a logbook. Never merge or overwrite flight histories by email alone.

## Step 4 — Production later

Production Supabase is already initialized but currently has no Auth users and is **not** connected to a deployed HeliLog production candidate. After staging is successful:

- Configure a separate Google OAuth client for the production Supabase callback and authorized origin.
- In [Production → Auth Providers](https://supabase.com/dashboard/project/xvmzvoldlajvnfxonrvn/auth/providers), enable Google with the production client only.
- Set [Production → URL Configuration](https://supabase.com/dashboard/project/xvmzvoldlajvnfxonrvn/auth/url-configuration) to the production Site URL, and allow `https://helilog-pwa.onrender.com/?helilog_oauth=google` and `https://helilog-pwa.onrender.com/?helilog_recovery=1`.
- Recheck Auth signup/anonymous settings, email/password compatibility, server-side invitation/allowlist strategy, and privacy controls.
- Test a separate candidate on an isolated origin before switching the existing V1 Render service. The production package has `googleEnabled:true` and an origin-pinned production Supabase configuration.
