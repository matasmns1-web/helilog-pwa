# HeliLog V2.12 — private beta and password-recovery acceptance checks

**Staging/test accounts only. Do not use real logbooks or medical details.**

1. In Supabase **Authentication → URL Configuration**, add **exactly** `https://helilog-v2-test.onrender.com/?helilog_recovery=1` to Redirect URLs. Set the Site URL to the HeliLog test host as appropriate; verify the Recovery email template uses the intended redirect.
2. Verify recovery mail delivery, spam handling and rate limits. The default Supabase email sender may not deliver to arbitrary friends; configure a properly authenticated SMTP provider before beta invitations.
3. On the login screen select **Forgot password?**, enter a fictional test account email, and verify generic instructions without account-existence disclosure. Also try an unknown email.
4. Open the recovery email. Verify it goes to the **Set a new password** page, never the logbook. Test mismatch and fewer than 12 characters (should remain on the reset page).
5. Set a matching password. Verify it returns to **Sign in** and the new password works. The previous password should fail. Repeat with an expired or malformed email link and confirm logbook records remain inaccessible.
6. Invite a **second independent fictional** test user from Supabase Auth and set up a separate pilot profile. Compare flights, aircraft, people, licences, medical data, print archives, signed corrections and backups in both accounts. Each user must see only their own rows.
7. Sign out and switch between accounts on the same browser, then verify no other account's records display. Repeat from two devices including offline queued edits and a deliberate conflict.
8. Verify anonymous requests to all six private HeliLog tables cannot read/write. Verify neither anon nor authenticated can directly execute the two correction trigger functions, while legitimate correction workflows still work.
9. Confirm new archives and signed addenda are immutable, account-scoped and recoverable without copying another pilot's information.
10. Verify independent encrypted backup restore using test-only records before inviting anyone to store genuine personal information.

**Do not declare multi-tenant isolation fully validated until steps 6–10 are actually run and pass.**
