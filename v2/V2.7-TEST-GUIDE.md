# HeliLog V2.7 — Offline Sync & Conflict Review Acceptance Guide

**Development branch:** `v2/2.7-offline-conflict-review`. **Not automatically released to the Render test website.** V1 production remains unchanged.

**Use fictional records only.** V2 is still a test system, not an EASA-authority-approved electronic logbook or validated electronic-signature service.

## Scope

V2.7 builds on the V2.6 login and signed endorsement workflow you already tested:

- A previously signed-in session may save aircraft, flight, other-pilot and qualification edits locally when the network is unavailable. Changes are queued per account, survive a browser restart in device storage and are retried once the workspace has a verified session and network.
- Normal reconnect uploads revision-checked pending items and pulls other device changes.
- When the same record changes on two devices, the old content and current cloud copy stay untouched until an explicit conflict decision. The **Cloud account → Offline edit conflicts** panel shows conflicting records and lets you compare the device and cloud copies.
- **Keep this device copy**: before re-uploading, HeliLog checks that the cloud and the pending local edit have not changed since review, then saves a full device-local recovery snapshot and rebases the queued operation on the verified cloud revision. The actual write still checks that revision.
- **Use current cloud copy**: after the same checks and local recovery snapshot, replace only the selected local record. Other pending items remain queued.
- Signed endorsements, archive-related flights/aircraft and all settings, including pilot profile settings, are excluded from this general tool. The existing reviewed pilot-profile recovery flow remains available. No archive records are rewritten.

## Test A — Offline queue and reconnect

1. Sign in online on both the web and installed app. Confirm the cloud sync status has settled.
2. On the installed app, disable connectivity **without signing out or closing the signed-in session**.
3. Add or edit a **fictional** aircraft or flight, save it and check for Offline/Pending status.
4. Restore connectivity while still signed in. Open **Cloud account → Check / sync now** if needed.
5. Confirm that the test website receives the edit with the same registration, flight duration and pilot function and eventually reports **Cloud synced**.
6. Check that a local offline change does not disappear when the session remains active and the page is revisited.

**Important:** Offline *account login or unlocking an app from a cold start while offline* is NOT guaranteed or supported in V2.7. A previously verified online session is still necessary for opening an account workspace. The queued changes persist in device storage but are not a substitute for a separately verified external backup.

## Test B — Conflict: choose cloud

1. Sign in on a web browser and an installed app with the same TEST account. Use the same fictional aircraft on both devices.
2. On the app, disconnect and change its registration to e.g. `LY-OFF-01`. Save.
3. On the website (online), change that same aircraft to `LY-WEB-01`. Wait for Cloud synced.
4. Restore the app connection and sync. Expected: **Conflict: needs attention**. Neither registration should be silently overwritten.
5. In **Cloud account → Offline edit conflicts**, click **Compare copies**. Verify that both names are visible, then choose **Use current cloud copy** and confirm.
6. After synchronization, verify `LY-WEB-01` on both devices. No unrelated records or endorsements should change.

## Test C — Conflict: keep device

1. Repeat Test B with different fictional registration values.
2. Click **Compare copies**, choose **Keep this device copy**, confirm and allow reconnection.
3. Verify the chosen offline registration is uploaded and later appears on the web; unrelated records remain unchanged.
4. If another device changes the cloud record while you are still reviewing, the saved preview must be rejected; start a new comparison.

## Protection checks

- The **Review** button must not be offered for a signed endorsement or an archive-linked record. Do not try to force edit signed or confirmed archive history.
- Archive/print confirmation remains blocked whenever there are outstanding sync conflicts or pending edits. The already-tested app → web signing → web archive → app archived-status workflow should still work after all devices show Cloud synced.
- A failed local safety-snapshot write must block conflict resolution. **Do not clear browser storage**, uninstall the PWA, or reset account data during a conflict.
- A device-local recovery snapshot is not an externally verified backup, and storage remains device/browser-specific.
- If HeliLog detects changes missed by the pending queue, it blocks the operation. Those cases require assisted recovery rather than automatic conflict resolution.
- If the cloud removed an aircraft/pilot still referenced by local flight/endorsement records, the normal conflict tool rejects the deletion.

## Deferred to V2.8+

- **Cloud archive integrity:** independently verify immutable signed and printed snapshots, reprint fidelity, page numbering, amendment continuity and cross-device consistency.
- **Backup and recovery:** scheduled encrypted/off-device backups, accessible restore tooling, verified recovery drills, auditability and retention controls.
- **Offline access hardening:** secure offline workspace unlocking, authentication expiration and re-verification policies, device encryption, storage migration to IndexedDB, and wider interrupted-write recovery.
