# HeliLog V2.19 — ICAO airport coordinates and custom helipads

**Environment:** `v2/development` / HeliLog TEST only. Production `main` remains V2.17.

## Add Flight: simpler location and UTC entry

- Departure place and Arrival place remain separate inputs, accepting ICAO identifiers or saved custom site codes (up to 12 characters).
- Both flight-time input labels explicitly read **Departure time (UTC, 24h)** and **Arrival time (UTC, 24h)**. HHmm and HH:mm and the custom 24-hour picker remain supported.
- The six manual lat/lon inputs and expandable coordinate section have been **removed from Add Flight**. HeliLog resolves the site coordinates automatically for civil twilight/night-time estimates and shows the calculated NIGHT minutes in the flight form.
- A local bundle of 18 Lithuanian/Baltic and nearby reference points resolves offline. For other four-letter ICAO codes, HeliLog attempts an online lookup using the [OpenFlights global airports database](https://openflights.org/data.php), approximately 1 MB for first use in each application session. OpenFlights is reference data (ODbL) and can be outdated; check the AIP.
- If the code is not in the database, or an internet lookup fails, HeliLog never invents a coordinate or quietly records zero automatic night minutes. Save a custom site under Settings, or disable automatic night-time calculation and enter minutes manually.

## Settings → Aerodromes & Helipads

- Dedicated management page accessed via Settings.
- For a known ICAO code, **Find ICAO coordinates** fills WGS84 latitude/longitude, which the user can verify. For an unregistered heliport/off-airport operating site, enter a custom 2–12 character code and its decimal coordinates. Examples: `BASE-1`, `HELI1` and `EYVI`.
- **Save site**, **Edit**, **Delete**. The directory lives in `S.siteLocations` and is synchronized per authenticated Supabase user using the existing settings kind. No schema migration or shared/global custom site directory.
- Saved locations take precedence over public reference coordinates, allowing the precise local helipad to be used. Previously saved flight-specific coordinates remain with each flight; no historical or signed pages are rewritten when a location is edited or removed.
- Custom saved sites work offline once synchronized to the device. The global airport index still needs an online fetch for airports outside the bundled codes.
- Latitude range `-90…90`, longitude `-180…180`; zero is permitted where valid, but both coordinates must be supplied. Site identifiers are validated and HTML-escaped before rendering.

## Limits

HeliLog continues calculating EASA/SERA civil twilight as the time the Sun's centre is below -6°, in UTC. The straight-line estimate uses the departure/arrival reference points rather than a GPS trace. This is a test feature, not an independently approved regulatory twilight calculation. Official AIP coordinates, national night definitions and the actual route take precedence.

## Suggested validation

1. Enter EYVI→EYVI with a UTC twilight-crossing time: automated coordinates and night minutes should appear without latitude/longitude fields.
2. Try unfamiliar ICAO EDDF while online: after reference data loads, the night-time calculation should update automatically.
3. In Settings, save `BASE-1` with WGS84 coordinates; return to Add Flight and use BASE-1 for both departure and arrival, confirming night calculation works offline.
4. Change BASE-1 coordinates, save and confirm the change syncs to a second TEST device.
5. Reopen an older V2.18 flight: its recorded snapshot and manual/automatic night setting remain unchanged unless explicitly edited.
6. Verify departure and arrival labels both visibly say **UTC, 24h** and the HHmm picker behavior remains unchanged.
7. Try an unknown site with auto enabled: the form must display Settings guidance and refuse automatic night save until resolved. Manual night override remains possible.
8. Confirm archived flight correction, logbook export, backup and cross-account separation still pass the established tests.

See `v2/v219-aerodromes-utc.test.cjs` for automated regressions.
