# HeliLog V2.11 — Interface cleanup acceptance checklist (TEST)

The focus is UI organization only. All storage, cloud sync, immutable print archive, endorsements, correction proposals, signatures, backup encryption, recovery and offline protections are unchanged.

## 1. Profile

1. Open **Profile** on desktop and installed iPhone/iPad.
2. Verify pilot identity card shows name, licence and competent authority with an Edit action.
3. Confirm **Medical** and **Licences & Ratings** are **collapsed by default**, each with a short visible summary.
4. Expand Medical, verify all certificate details, edit, save and return. Medical should reopen, and its summary should reflect the saved fields.
5. Expand Licences & Ratings; add, edit and delete a *fictional* qualification. Confirm all actions remain available inside the expanded section.
6. Confirm **Log out** remains available on Profile and no backup/recovery or Test Mode sections appear there.

## 2. Settings

1. Open Settings from desktop sidebar and from **More** on mobile.
2. **Existing logbook import** should show previously imported opening totals or its one-time import button. Its edit form must cancel and save back to Settings.
3. **Data integrity check** should still run and show a read-only report.
4. **Test Mode** should be hidden for a signed-in cloud workspace (it is not a normal cloud operation). Existing local Test Mode remains available when supported.
5. **App & device** should display PWA installation/offline-app information without losing the existing Install button.
6. **Backup & recovery** should open the separate Backups page.

## 3. Cloud Account and Backup & Recovery

1. Cloud Account should show connection, synchronization, record conflicts and archive verification as before.
2. Tap **Manage backups** to open the new dedicated Backup & Recovery page.
3. Confirm the page contains **Cloud backup health & retention, Backup now, encrypted downloads, encrypted-file inspection, isolated recovery drill, guarded cloud restore, full JSON download and recovery-package inspection**.
4. Run a read-only health check, download and inspect a fictional encrypted snapshot. Results must keep you on the Backup & Recovery page.
5. The full cloud-account replacement button remains disabled; the existing signed-archive and correction protections are unchanged.
6. Confirm new desktop navigation and mobile More links work, and the installed app continues to support offline logging and corrections.

## 4. Regression rules

- No data migrations, reset or deletion.
- Existing print archives, signed endorsements and correction addenda must remain identical before and after the UI release.
- V2.10 remains the last user-accepted baseline until V2.11 manual testing passes.
- Only V2 test site is updated; V1 production remains untouched.
